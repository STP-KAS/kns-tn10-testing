# S3 snapshot run (TN10 only) — wallets 700–20699

- Wallets: 20,000 new BIP44 addresses `m/44'/111111'/0'/0/{700..20699}` from the existing snapshot mnemonic (appended to
  addresses.csv / wallets.jsonl / privkeys jsonl; backups `*.bak-s3-2026-09-24T21-31-39+0200` and `*.bak-s3b-2026-09-24T21-35-01+0200`).
- Names: `stp-s3-w{index:05d}-d{n}`; 700–10699 get d0–d2 (3 names), 10700–20699 get d0–d1 (2 names) → 50,000 names.
  Indexer pre-check of all candidate names: `s3-name-precheck.json` (all available).
- Funding (treasury `kaspatest:qzffl5…0ldx`, key loaded in-process only): `scripts/treasury-fund-s3.mjs`
  → 120 TKAS per 3-name wallet, 85 TKAS per 2-name wallet (measured cost 35.0352 TKAS/name incl. commit+reveal fees).
  Logs: `desk-fund-700-20699.log/.jsonl/-status.json`; on-chain audit: `scripts/s3-funding-audit.mjs` → `s3-funding-audit.json`.
- Inscribing: `scripts/s3-supervisor.mjs` runs `scripts/kns-snap-s3.mjs` workers over 500-wallet ranges
  (`s3-{from}-{to}.jsonl`, `s3-status-{from}-{to}.json`, `s3-{from}-{to}.pid`, `s3-stdout-{from}-{to}.log`).
  Each name uses `scripts/kns-s3-create.mjs` (copy of kns-smoke-create.mjs that reuses stranded commits and
  builds the reveal from the commit's own change output on the same RPC node).
- Controls: `s3-max-workers` (number, read every 30 s); touch `s3-STOP` to stop launching new workers;
  `scripts/s3-drain-workers.sh <pids>` stops workers only between names. Workers pause when MemAvailable < 800 MB;
  the supervisor adds workers only when MemAvailable ≥ 1200 MB. All s3 processes have raised oom_score_adj so the
  kernel kills them before the TN10 kaspad/miner farm.
- Progress: `scripts/s3-progress.sh`.
